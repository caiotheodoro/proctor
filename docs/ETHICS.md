# Ethics

The author is a Forward Deployed Engineer at TrueFoundry. TrueFoundry sells a gateway that can prove an agent was allowed to call a tool. Proctor measures the question that proof does not answer. That is a conflict of interest and it is named here before any result.

Containment, checkable from the tree:

- `docs/PRE-REGISTRATION.md` freezes in a commit that touches only that file and `docs/DECISIONS.md`, and it freezes before any package exists.
- No hypothesis reads a TrueFoundry tenant, a customer trace, or a live gateway. The arms are `flag_everything`, `schema_only`, one open-weight judge, and a model trained on the synthetic train split.
- The fixture is generated from a seed. Accounts, files, and messages are not copies of anyone's. There are no human subjects.
- Negative results ship in the same card as positive ones. H1 can fail. H4 can fail. A failed hypothesis is a result.
- Dollars do not appear. There is no price table and no customer spend.
- Keys, if a judge server is used later, live in `.env`. `make privacy-gate` fails the build on a key-shaped string in a tracked file.

No vendor funded this work. No vendor reviewed it before the protocol froze. The laptop is not a training device; if the trained arm never runs, the card says the claim is unmet rather than borrowing a smaller model and keeping the sentence.

The project takes no position on any gateway product beyond the comparison H1 and H3 define: a schema check against a floor that flags everything, on a population the oracle can recompute.
